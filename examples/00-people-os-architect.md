## Запрос

> Проведи аудит нашей HR-системы. IT-интегратор, 45 человек: продажи 12, пресейл 6, внедрение 15, поддержка 6, бэк-офис 6. Что есть: оргструктура, положение о премиях для отдела продаж, шаблон оффера. Чего нет: описания уровней, плана адаптации, регулярной оценки. Отток за год 22%, добровольный 15%, среди ушедших 3 сильных инженера. Вакансии закрываются в среднем за 65 дней.

## Ответ агента

Вот полный аудит вашей HR-системы по методологии People OS. Главный вывод: **из 6 этапов жизненного цикла ни один не закрыт полностью**, а два критических — адаптация и развитие — не имеют ни артефактов, ни показателей. Это объясняет уход 3 сильных инженеров.

### Ключевые цифры

- За год ушло **~10 человек** (22%), из них **~7 добровольно** (15%)
- **43% добровольно ушедших — сильные** сотрудники (3 из 7) — это критический сигнал
- Срок закрытия вакансии **65 дней** — в 1,5 раза выше бенчмарка IT-рынка (35–45 дней)

### Аудит по 6 этапам жизненного цикла

| Этап | Артефакт есть? | Показатель есть? | Риск | Первый шаг |
|---|---|---|---|---|
| **Потребность** | ⚠️ Частично: оргструктура есть, но описания задач на первый год нет | ⚠️ Срок закрытия считают (65 дн.), но без целевого значения | 🔴 Высокий: вакансии «по запросу», без привязки к бизнес-задаче | Шаблон заявки: задачи на год + результат + целевой срок 40 дней |
| **Отбор** | ⚠️ Частично: шаблон оффера есть, но нет единых вопросов и шкалы | ❌ Нет: воронка не ведётся | 🔴 Высокий: каждый руководитель оценивает по-своему → ошибки найма | Scorecard: 5 вопросов + шкала 1–4 для каждой роли |
| **Адаптация** | ❌ Нет: план 30-60-90 отсутствует | ❌ Нет: время до первого результата не считают | 🔴 Критический: новичок осваивается сам, часть уходит на испытательном | План 30-60-90 для инженеров внедрения |
| **Развитие** | ❌ Нет: описания уровней нет, оценки нет | ❌ Нет: доля внутренних назначений не считается | 🔴 Критический: сильные не видят роста → уходят | Описать 3 уровня для инженеров: поведение, автономность, зона влияния |
| **Удержание** | ⚠️ Частично: премии только для продаж (12 из 45 чел.) | ⚠️ Частично: отток без разделения по отделам | 🔴 Высокий: 43% ушедших — сильные; пересмотр зарплат реактивный | Диапазоны вознаграждения для инженеров + правило пересмотра |
| **Выход** | ❌ Нет: exit-интервью не фиксируется | ❌ Нет: причины ухода не анализируются | 🟡 Средний: знания уходят с людьми | Шаблон exit-интервью (проводит HR, не руководитель) |

### Правило трёх документов (компания до 50 человек)

| Документ | Статус | Комментарий |
|---|---|---|
| 1. Как устроены уровни | ❌ Отсутствует | Сотрудники не понимают, как расти |
| 2. Как считается вознаграждение | ⚠️ Только для продаж | Покрывает 12 из 45 человек; для остальных 33 — правил нет |
| 3. Что происходит в первые 90 дней | ❌ Отсутствует | Новичок зависит от доброй воли руководителя |

**Вердикт:** 0 из 3 документов закрыты полностью. Система держится на личных отношениях руководителей.

### Метрики: что мерить

| Метрика | Сейчас | Цель | Статус |
|---|---|---|---|
| Добровольный отток | 15% | ≤10% | 🔴 Выше нормы |
| Доля сильных среди ушедших | ~43% | ≤15% | 🔴 Критично |
| Срок закрытия вакансии | 65 дней | ≤40 дней | 🔴 В 1,5× выше бенчмарка |
| Время до первого результата | Не считается | Определить по ролям | ❌ Нет данных |
| Доля внутренних назначений | ~0% | ≥30% | 🔴 Нет роста изнутри |
| Разброс результатов внутри роли | Не считается | Определить | ❌ Нет данных |

### Маршрутизация к профильным агентам

| Этап | Агент | Готовый вопрос для агента |
|---|---|---|
| Потребность | Workforce & Succession Agent | «У нас 15 инженеров внедрения, отток 15%, срок закрытия 65 дней. Рассчитай целевую численность с учётом оттока. Нужен ли буфер?» |
| Потребность | Org Design Agent | «Отдел внедрения 15 человек, один руководитель. Нужно ли выделять тимлидов? Какой диапазон управляемости?» |
| Отбор | Recruiting Agent | «Составь scorecard для инженера внедрения: 5 компетенций, вопросы, шкала 1–4. Какой EVP для IT-интегратора?» |
| Адаптация | Onboarding Agent | «Создай план 30-60-90 для инженера внедрения. Критерий на 90-й день — самостоятельное ведение проекта.» |
| Развитие | Talent Agent | «Опиши 3 уровня для инженера внедрения по модели: задачи, автономность, зона влияния, работа с ошибками.» |
| Удержание | Rewards Agent | «Рассчитай диапазоны Total Rewards для инженеров внедрения (Junior/Middle/Senior). Нефинансовые факторы?» |
| Выход | Recruiting Agent | «Составь шаблон exit-интервью. Какие вопросы выявляют системные причины, а не эмоции?» |

### План на 90 дней (3 шага)

**Шаг 1. Уровни для инженеров внедрения (дни 1–30)**

- Описать 3 уровня (Junior / Middle / Senior) — поведение, автономность, зона влияния
- Цикл: собрать ожидания руководителей → описать → провести калибровку → скорректировать
- **Метрика:** 100% инженеров распределены по уровням с обоснованием

**Шаг 2. План адаптации 30-60-90 (дни 15–60)**

- Создать план для инженеров внедрения, затем адаптировать для других ролей
- Цикл: выяснить причины ухода 3 инженеров → план для следующего новичка → чек-ин на 30/60/90 день
- **Метрика:** 0 уходов на испытательном среди следующих 3 наймов

**Шаг 3. Диапазоны вознаграждения (дни 30–90)**

- Диапазоны зарплат по уровням + правило пересмотра раз в 6 месяцев
- Цикл: рыночные данные → диапазоны → первый пересмотр → масштабировать на другие роли
- **Метрика:** Добровольный отток инженеров ≤10% в следующие 6 месяцев

---

Все три шага начинаются с отдела внедрения (15 человек, самый большой, самый болезненный отток), а затем масштабируются на остальные подразделения.
